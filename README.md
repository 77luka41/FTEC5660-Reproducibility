I used DeepSeek to run Tree of Thoughts on Game of 24. I compared the original LLM evaluator with an exact arithmetic evaluator. In both versions, the LLM generates the calculation steps and final expression.

## Main results (V3)

I ran five puzzles (dataset indices 903-907) three times with each evaluator, for 30 runs in total.

| Metric | LLM evaluator | Exact-tool evaluator |
|---|---:|---:|
| Successes | 9/15 | 11/15 |
| Mean trial accuracy | 60.0% | 73.3% |
| Sample variance of trial accuracy | 0.280000 | 0.013333 |
| Top-1 accuracy | 60.0% | 73.3% |
| Mean API attempts per puzzle | 48.67 | 8.80 |
| Mean reported tokens per puzzle | 24,576 | 3,881 |
| Mean seconds per puzzle | 46.90 | 8.82 |
| Runtime/budget errors | 0 | 0 |

Trial accuracies were **0%, 100%, 80%** with the LLM evaluator and **80%, 60%, 80%** with the exact evaluator. The average increased by 13.3 percentage points, although the exact evaluator performed worse in the second trial. It also failed all three attempts on puzzle 906, which the baseline solved twice. With only five puzzles and three repeats, this result needs further testing on a larger sample.

The exact evaluator adds exhaustive arithmetic checking to the search. The improvement therefore applies to this tool-assisted setup. The paper's 74% GPT-4 result used a different model, task sample and search setup, so it is not directly comparable with my 73.3% result.

## Source and changes

Original project: [princeton-nlp/tree-of-thought-llm](https://github.com/princeton-nlp/tree-of-thought-llm), [paper](https://arxiv.org/abs/2305.10601). I used commit `8050e67d0e3a0fddc424d7fa5801538722a4c4cc`. The authors' source package and MIT license are included.

I kept the original search loop, Game of 24 task, user prompt templates and dataset. `reproduce_v3.py` connects these to the proposal validation and evaluation functions at runtime. The recorded hashes check which source files were used.

Both versions use search width 3, up to eight valid proposals per parent, one value sample and the same prompts and resource limits. Only the evaluator differs. Invalid calculation steps are rejected. The exact evaluator checks whether the remaining numbers can reach 24 and assigns a score. Final expressions are generated by the LLM and checked using exact fractions and the authors' evaluator.

The settings are in `v3_config.json`. I fixed them before running V3, after investigating the earlier V1/V2 failures.

## Evaluation protocol

- Indices 903-907 were fixed before V3 inference and had not been run in V1/V2. Each arm runs these five puzzles in three trials. The 15 outcomes per arm are repeats of five distinct tasks.
- Primary accuracy is success-any among at most three retained final expressions. An expression must use the original four numbers exactly once and equal 24 using only +, -, * and /. Top-1 accuracy is also reported.
- Trial accuracy is computed over five puzzles; the mean, sample variance and sample standard deviation are computed over three trial rates.
- Both arms use width 3, at most eight valid proposals per parent and one value sample. Invalid arithmetic is rejected and logged without repair. A single remaining non-24 value ends a branch; a value numerically equal to 24 triggers an LLM-generated final expression.
- The baseline uses the authors' LLM value routine with brief reasoning allowed before an exact final label. The modified arm uses exhaustive reachability with exact fractions over one to three remaining values. It returns reachability and scores, not an answer.
- Arms alternate execution order and reset value caches between instances. Tool memoization is scoped to one instance. Python/NumPy seeds do not control provider decoding.
- Each instance permits at most 80 API attempts or 60,000 reported tokens. The last response can cross the token threshold. Errors and budget failures count as failures, and interrupted runs are kept in the logs.
- V3 uses different tasks, search settings and adapters from V2. The evaluator comparison uses the two V3 groups only.

## Run fresh inference

Set `DEEPSEEK_API_KEY` through Colab Secrets or an environment variable. Do not paste its value into code, command history, GitHub or a recording.

```bash
python reproduce_v3.py --preflight
python reproduce_v3.py --probe
python reproduce_v3.py --resume
```

Results are written to `experiment_runs/tool_evaluator_v3/`. The probe runs a separate search on `1 2 3 4` and is excluded from the main accuracy calculation. The main experiment runs all 30 instances with the limits described above. Seeds control Python/NumPy, but the API responses can still vary.

For fresh inference in Colab, add a Secret named `DEEPSEEK_API_KEY` and enable notebook access. Run the separate toy probe first:

